
\subsection{Invariant Generation for Loops}
{Given a C function, a target loop, its symbolic entry precondition, and an LLM, $\mathrm{LoopInvGen}$ returns the function annotated with a candidate invariant. Its aim is to find a property that holds at loop entry and is preserved by every iteration, thereby supporting verification of the enclosing function.}

{Generation has three main stages: symbolic analysis, template-based synthesis, and verification-guided refinement. After the LLM examines the loop's behavior, symbolic execution analyzes a single-iteration unfolding to identify unchanged variables and update patterns. The resulting classifications and loop-entry facts constrain invariant templates, while the LLM supplies the predicates needed to summarize repeated iterations. The candidates are inserted into the function and checked by the verifier; failures trigger refinement using both verifier feedback and symbolic context.}

{A key design choice is to process nested loops from the innermost outward. At the outer-loop boundary, a suitable symbolic entry precondition for an inner loop is not yet available, so its candidate invariant is generated directly from code context without a symbolic precondition or template. The outer loop can then use the annotated body and symbolic information to construct its templates. The complete algorithms are given in \appref{app:loop-analysis}.}
