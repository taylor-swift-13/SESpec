
\DIFbluesubsection{RQ7: What does \toolname\ cost in time, tokens, API calls, and memory?}
\label{subsec:rq7-cost}

\DIFaddbegin
This cost analysis is scoped to the \textbf{\toolname-400} study in Section~\ref{sec:large-scale-experiment}; it is not collected over the established benchmark families in Section~\ref{sec:experiments}. We use this scope because \textbf{\toolname-400} is the goal-independent setting in which \toolname, its ablations, \autospec, and \specgen\ are run under the same Pass@1 protocol. Fig.~\ref{fig:rq7-cost} reports average cost per valid run across the cost-accounted models. We report wall-clock time, token use, and API-call counts. Memory use is negligible: the process never exceeds \(\sim 500\)~MB peak RSS across the evaluated benchmarks.
\DIFaddend

\DIFaddbegin
The token cost is for one complete Pass@1 attempt on \textbf{\toolname-400}, including generation, verification, and repair. \toolname's verifier-guided iterative refinement raises the raw token count, but most of the extra tokens are repeated input-side context rather than longer generated specifications. Such context is cacheable across refinement calls, so the practical cost gap is smaller than the total-token gap suggests. Fig.~\ref{fig:rq7-cost} also shows that wall-clock time and API-call counts grow much less sharply than raw tokens.
\DIFaddend

\begin{finding}
\textbf{Finding (RQ7).} \toolname's added framework complexity mainly appears as higher token use; its wall-clock time and API-call count are much closer to the baselines than the raw token totals alone suggest.
\end{finding}
