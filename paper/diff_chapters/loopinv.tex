The general loop invariant generation problem can be defined as follows:
\begin{definition} Given a loop $l:\!$ \texttt{while B do C} of program $\mathcal{P}$, a precondition $P$ that holds at entry $l$, and an (optional) postcondition $Q$, the loop invariant generation problem is to find a logical formula $\textit{Inv}$ 
%over atomic memory locations of $P$ 
that satisfies the following conditions:
\begin{itemize}
    \item \textbf{Base:} $P \Rightarrow \textit{Inv}$, i.e., the invariant $\textit{Inv}$ holds initially;
    \item \textbf{Preservation:} $\{\textit{Inv} \land B\}\ C\ \{\textit{Inv}\}$, i.e., if $\textit{Inv}$ holds at the start of a loop iteration and loop condition $B$ is true, executing loop body $C$ preserves $\textit{Inv}$;
\item  \textbf{Termination:} $\textit{Inv} \land \neg B \Rightarrow Q$, i.e., upon loop termination, $B$ turns false, $\textit{Inv}$ remains true and implies postcondition $Q$.
\end{itemize}
  \label{Def:invariant}   
\end{definition}

Among these conditions, the postcondition serves as the verification target, whose objective is to synthesize sufficiently strong invariants that imply it. Our invariant generation algorithm, presented below, is designed to produce strong invariants even in the absence of postconditions. We achieve this through a combination of symbolic execution and Large Language Models (LLMs), using symbolic-state-guided invariant templates that expose path conditions, variable classifications, frame facts, and relation placeholders derived from symbolic loop-entry and loop-body information.
The effectiveness of this approach is experimentally demonstrated in Section~\ref{sec:inv_experiments}.
