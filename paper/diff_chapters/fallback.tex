\subsection{LLM Fallback}
\label{sec:llm-fallback}

The LLM fallback wraps Algorithm~\ref{alg:funspec-gen} and has two triggers: (i) self-recursion or recursive data structures, routed at function entry because the executor neither computes recursive fixpoints nor enumerates unbounded shape cells; and (ii) $\textit{SP}$ returning $\textit{SymExecFailed}$ at function exit, covering external calls, path explosion, runtime errors, and other unsupported program features. Loops and ordinary callees instead use $\mathrm{LoopInvGen}$ and recursive $\mathrm{FuncSpec}$; their verifier failures go to the separate refinement layer.

\rev{To replace a missing symbolic summary, the fallback LLM uses the code, available symbolic states and path conditions, prior callee and loop summaries, and an ACSL skeleton to propose preconditions, assigns clauses, postconditions, or inductive predicates. Prompt and task details appear in \appref{app:fallback}.}

Fallback candidates are retained only if Frama-C/WP proves them under the configured memory model and solvers; failures enter refinement (Section~\ref{sec:refinement}). Accepted candidates can cover cases outside the exact symbolic-execution fragment as sound over-approximations, but lack the strongest-postcondition guarantee of Proposition~\supref{thm:sp-sound-complete} in \appref{app:sp-proof}.
