Table~\ref{tab:dataset_overview} classifies 395 programs by control flow and
data type; blue cells need loop invariants, while red cells also need function
contracts. \toolname\ verifies 353/395 (89.4\%), including pointer/struct and
linked-list cases. It reaches about 96\% on linear-loop and iteration-free
programs but 77\% on nonlinear loops, 63\% on nested/multiple loops, and
0/3 on external/recursive calls. Thus lines of code alone poorly predict
difficulty; the required invariant or summary matters more.

The weak classes have different causes. At nested or multiple loops,
symbolic execution often lacks precise loop preconditions, leaving the LLM
to infer relations across phases or loops. Nonlinear programs can require
arithmetic facts, helper functions, or inductive definitions beyond the SMT
budget. Recursive structures need inductive predicates beyond the finite
memory model, while external and recursive calls lack an exact symbolic
summary. The LLM fallback covers some simple recursive cases
(\appref{app:cases}); broader limits are discussed in
\rev{\appref{sec:limitations}}.

\begin{finding}
\textbf{Finding (RQ1).} \toolname\ produces a \emph{Valid} specification for $89.4\%$ ($353/395$) of programs spanning linear/non-linear loops, memory, and linked lists; the residual failures concentrate on reasoning-heavy cases involving nested/multi-loop relations, non-linear arithmetic, recursive data structures, or external/recursive calls outside the symbolic-execution fragment.
\end{finding}
