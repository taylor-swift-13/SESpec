
\subsection{RQ7: What does \toolname\ cost in time, tokens, API calls, and memory?}
\label{subsec:rq7-cost}

This cost analysis is scoped to the \textbf{\toolname-400} study in Section~\ref{sec:large-scale-experiment}; it is not collected over the established benchmark families in Section~\ref{sec:experiments}. We use this scope because \textbf{\toolname-400} is the goal-independent setting in which \toolname, its ablations, \autospec, and \specgen\ are run under the same Pass@1 protocol. \rev{The paired comparison in Fig.~\ref{fig:rq7-cost} covers all 400 programs on \texttt{gpt-5.4-mini} and reports cost per attempted program, including failures. The original \autospec\ time, API-call count, and validity label are retained.} Memory use is negligible: the process never exceeds \(\sim 500\)~MB peak RSS across the evaluated benchmarks.

\rev{Each solid segment in Fig.~\ref{fig:rq7-cost} sums the cost of valid runs and divides it by all 400 attempts; the hatched segment uses the same denominator for failed runs. Failures account for 519.4 of \autospec's 932.1 seconds and 235.0 of \specgen's 375.5 seconds per attempt, compared with 48.1 of \toolname's 318.2 seconds. Dividing total time by valid-run count gives 338.6 seconds per obtained valid \toolname\ specification, versus 1,462.1 for \autospec\ and 758.6 for \specgen\ on this cohort. \toolname's 83.8k tokens per attempt include repeated refinement context; token counts apply no cache discount.}

\begin{finding}
\textbf{Finding (RQ7).} \rev{\toolname's added framework complexity mainly appears as higher token use; its wall-clock time and API-call count are much closer to the baselines than the raw token totals alone suggest.}
\end{finding}
